Materials keeps the filament and resin a farm has on its shelves. Its catalogue is the OpenPrintTag material database, with the materials, brands and packages of many makers, and a person adds materials of their own beside it. For each material it keeps the spools in stock: how much is left on each, its package, where it is kept and a note. A spool used up or lost is archived, as in Connect's Warehouse: it stays listed but leaves the stock. The list filters by brand, type, colour, location and stock, and each person's stars and filters are their own.

Before you switch it on, decide two things:

- **Where its data goes.** The catalogue, the spools and the locations live in a database of the extension's own. The install dialog asks for it: a SQLite file in the extension's data directory, which is the default, or a Postgres database.
- **Where the catalogue comes from.** It is downloaded from GitHub over https when a person loads it under Settings, Extensions, Materials. A server with no way out sets `catalogue_url` to a mirror inside its network, and `catalogue_ca` to the certificate that mirror's is signed with.

The server decides every request before the extension sees it. Reading takes `view_resource` on the extension, and changing anything takes `operate_resource`. Changing the material on a printer tool also takes `operate` on that printer: the extension asks the server, as itself, whether the person has it. It keeps each answer for 30 seconds, so a person whose `operate` is taken away may still change that printer's tools for up to 30 seconds. A custom material belongs to the person who made it; the spools and locations are shared.

The README in `extensions/materials` lists the limits and the error codes.

- codeload.github.com port 443 from the process: GitHub serves the default catalogue archive from there after a redirect. Sends: Only the request for the archive.
